## Defect found and corrected

The PostgreSQL rollback test found that `createNotificationWithNavigation` opened its own transaction during a lead assignment. A later transfer failure rolled back ownership and assignment rows but left an already committed notification behind.

The helper now reuses the existing assignment transaction when one is active. Notification context reads also use the existing transaction-aware database accessor. Outside an assignment transaction, the helper retains its independent transaction. Notification and WhatsApp outbox writes remain grouped together. The existing database regression test now verifies that notifications, ownership, assignment rows, audit rows, and routing progress roll back together.

No endpoint, response contract, schema, migration, or authorization rule changed.

## Database test coverage

All three previously skipped database suites were enabled:

- Read-only tenant isolation: employee rows/totals, foreign employee-ID rejection, and team ownership across the configured workspaces.
- Rotation: disposable local database migration from legacy rows, fresh-schema migration, exact pass counts, concurrent worker serialization, concurrent rule edits, snapshot preservation, rollback, manual assignment, and CRM-action stop behavior.
- Meta routing: save/reset of form routing while preserving sibling settings, within a transaction that is rolled back after verification.

The shared test-provider helper now accepts an organization ID. Database fixtures create that organization so notification and audit foreign keys exercise valid tenant context. Rotation fixtures remain unowned legacy leads; their expectations now reflect the existing SaaS rule that legacy leads receive no tenant admin alerts. Test cleanup also restores fixture-user active status to keep cases independent.

Rotation test databases are created with unique `rotation_test_...` names and removed by the existing suite cleanup. Meta fixtures are rolled back. The read-only tenant suite creates no fixtures. External provider and notification transports are mocked in the database tests.
